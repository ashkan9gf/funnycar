# FunnyCarIR — گزارش ممیزی آمادگی انتشار

این گزارش، یافته‌های بررسی اولیه مخزن را از تست‌های واقعاً اجراشده جدا می‌کند. هیچ APK/AAB یا تست روی دستگاه فیزیکی در این تغییرات ادعا نشده است.

## اصلاحات اعمال‌شده در شاخه audit/fix-release-readiness

- تنظیمات Next.js دیگر خطاهای TypeScript را نادیده نمی‌گیرد و Strict Mode فعال شده است.
- دستور `db:push` دیگر `--accept-data-loss` را به‌صورت خودکار اجرا نمی‌کند.
- در AndroidManifest، پشتیبان‌گیری خودکار برنامه غیرفعال شده است.
- WebView debugging از حالت فعال به غیرفعال تغییر کرده است.
- فایل‌های خروجی کامپایل اندروید و کلیدهای keystore به gitignore افزوده شده‌اند.
- workflow کنترل کیفیت وب اضافه شده است تا نصب وابستگی‌های قفل‌شده، lint و production build در GitHub Actions بررسی شوند.
- مسیر ساخت آفلاین اندروید با Next.js static export و Capacitor اضافه شده و workflow تولید APK آزمایشی را اجرا می‌کند؛ این مسیر هنوز نیازمند عبور کامل CI است.
- مهاجرت SaveManager مقاوم‌تر شده است: مقادیر NaN/Infinity و داده‌های ناقص سیو پاک‌سازی می‌شوند و دسترسی مسدودشده به localStorage نباید به‌تنهایی بازی را متوقف کند.
- فایل keystore آزمایشی از شاخه ممیزی حذف شده است.

## موانع انتشار که هنوز باید حل/تأیید شوند

1. فایل `.env` از شاخه ممیزی حذف شده است، اما در شاخه `main` و تاریخچه commitهای قبلی هنوز ممکن است موجود باشد. اگر فایل حاوی اعتبارنامه واقعی بوده، آن اعتبارنامه باید تعویض شود؛ حذف فایل در commit جدید، تاریخچه قبلی را پاک نمی‌کند. برای پاک‌سازی کامل تاریخچه فقط پس از بررسی اثرات و هماهنگی با همکاران اقدام شود.
2. پوسته Android قدیمی `android-build/java/.../MainActivity.java` به `assets/www/index.html` وابسته است و با خروجی Next.js standalone هم‌مسیر نیست. برای کاهش ابهام، مسیر جدید Capacitor برای بسته آفلاین در حال آزمون است؛ APK فقط پس از موفقیت کامل workflow قابل تأیید است.
3. اسکریپت `scripts/build-android-web.sh` در زمان export، API و فایل‌مرورگر مخصوص سرور را موقتاً از مسیر route خارج می‌کند و سپس حتماً آن‌ها را برمی‌گرداند؛ خروجی باید وجود `out/index.html` و مدل اصلی سه‌بعدی را تأیید کند.
4. نسخه داخل AndroidManifest برابر 0.2.5 / versionCode 5 است؛ باید با نسخه واقعی انتشار و سیاست افزایش versionCode هماهنگ شود.
5. فایل `db/custom.db` در مخزن track شده است. محتوای آن و نیاز runtime باید بررسی شود؛ حذف یا جایگزینی آن بدون اثبات اینکه داده ضروری ندارد انجام نشود.
6. خریدهای درون‌برنامه‌ای، حریم خصوصی، مجوزهای نهایی، اندازه بسته، ABI و امضای release هنوز باید روی خروجی نهایی بررسی شوند.
