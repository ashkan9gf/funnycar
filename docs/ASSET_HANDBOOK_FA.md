# بخش ۰ — واژه‌نامه: اول این کلمه‌ها را بفهمیم

قبل از هر چیز، همه اصطلاحاتی که در این پروژه می‌شنوید، با زبان ساده:

| اصطلاح | یعنی چه؟ | مثال روزمره |
|---|---|---|
| **Asset** | هر «موجودی» که داخل بازی استفاده می‌شود و در فایل جدا ذخیره شده: تصویر، صدا، فونت... | عکس ماشین بازیکن یک Asset است |
| **Sprite** | یک تصویر دوبعدی که در بازی حرکت/رسم می‌شود | همان عکس ماشین، وقتی داخل بازی نمایش داده شود |
| **Sprite Sheet** | یک عکس بزرگ که چند فریمِ یک انیمیشن کنار هم داخلش چیده شده | ۶ عکس دود، کنار هم در یک فایل |
| **Frame (فریم)** | یکی از آن عکس‌های کنار هم | تک‌تصویرِ دودِ بزرگ‌شده |
| **FPS** | Frames Per Second — تعداد فریمی که در هر ثانیه پخش می‌شود | 8 FPS یعنی انیمیشن دود ۸ بار در ثانیه عوض می‌شود |
| **Texture** | همان تصویر، وقتی از دید حافظه گرافیکی نگاه کنیم | — |
| **Atlas** | چند Sprite کوچک که در یک فایل چسبیده شده‌اند تا بازی سریع‌تر شود | همه آیکون‌های UI در یک عکس |
| **Transparent Background** | پس‌زمینه شفاف؛ یعنی دور ماشین «هیچی» باشد نه رنگ سفید | ماشین روی جاده بدون مربع سفید دورش |
| **PNG** | فرمت تصویر با پس‌زمینه شفاف — بی‌افت | عکس ماشین |
| **WebP** | مثل PNG ولی حجم کمتر (پشتیبانی اندروید: کامل) | عکس Splash |
| **JPG** | حجم کم ولی شفافیت ندارد و با هر ذخیره مجدد افت می‌کند | فقط برای پس‌زمینه‌های پر (مثل Splash) |
| **Resolution** | تعداد پیکسل‌های تصویر (عرض×ارتفاع) | 256×448 |
| **Tile (کاشی)** | تصویری که کنار کپی‌های خودش می‌نشیند و زمین می‌سازد | کاشی آسفالت جاده |
| **Seamless** | لبه‌های کاشی طوری است که کنار خودش درز نیفتد | جاده بی‌درز |
| **Placeholder** | تصویر موقتِ برچسب‌دار که تا رسیدن Asset واقعی جایش را می‌گیرد | مربع سبز نوشته‌دار PLACEHOLDER_VEHICLE |
| **Manifest** | فهرست رسمی «شناسه → مسیر فایل» در پروژه | src/game/data/assets.manifest.ts |
| **Import** | وارد کردن Asset به بازی | گذاشتن فایل در پوشه درست + ثبت در manifest |
| **Sample Rate** | تعداد نمونه‌گیری صدا در ثانیه (کیفیت صدا) | 44100Hz استاندارد |
| **Mono/Stereo** | تک‌کاناله/دوکاناله بودن صدا | برای بازی: همه Mono (نصف حجم) |
| **Loop** | تکرار شدن صدا/انیمیشن | موسیقی باید بدون «پرش» تکرار شود |
| **OFL** | مجوز آزاد فونت — اجازه استفاده تجاری | فونت وزیرمتن |
| **RGB / Palette** | رنگ‌بندی تصویر؛ RGB استاندارد است | — |

# بخش ۱ — از صفر تا اولین Asset (گام‌به‌گام)

هدف این بخش: شما در کمتر از ۴۵ دقیقه، اولین Asset واقعی را بسازید و وارد بازی کنید. حتی اگر تا امروز هیچ ابزاری باز نکرده باشید.

## گام ۱ — چه برنامه‌هایی لازم دارم؟ (همه رایگان)

| کار | ابزار پیشنهادی | چرا؟ |
|---|---|---|
| ساخت/ویرایش تصویر | **Photopea** (photopea.com — داخل مرورگر، بدون نصب) | شبیه فتوشاپ است، رایگان، فارسی‌ها را می‌فهمد |
| تولید تصویر با AI | هر ابزار تولید تصویر (Promptهای آماده در ASSET_GENERATION_GUIDE_FA.md) | سریع‌ترین راه برای کسانی که نقاشی نمی‌کنند |
| حذف پس‌زمینه | Photopea (Magic Cut / Select Subject) یا remove.bg | — |
| تغییر اندازه/فرمت | Photopea (Export As) یا squoosh.app (سایت گوگل، فشرده‌سازی) | squoosh برای تبدیل به WebP عالی است |
| ساخت Sprite Sheet | **Libresprite** (رایگان، دسکتاپ) یا Photopea (چیدمان دستی) | — |
| ضبط/ویرایش صدا | **Audacity** (رایگان، دسکتاپ) | استاندارد دنیا برای کار صدای مبتدی |
| برنامه‌نویسی لازم؟ | **نه!** شما فقط فایل می‌سازید و در پوشه می‌گذارید | کد از قبل آماده است |

## گام ۲ — بفهمید چه Assetای را باید بسازید

1. فایل `docs/ASSET_INVENTORY_FA.md` را باز کنید.
2. هر Asset با وضعیت ⬜ یعنی «هنوز ساخته نشده» — از **Batch 1** شروع کنید (جدول‌ها ستون Batch دارند).
3. مشخصات دقیق (ابعاد، فرمت، نام فایل، مسیر) را از همان جدول بردارید. **هیچ چیزی را حدس نزنید** — همه چیز در جدول هست.

## گام ۳ — تصویر بسازید (دو راه)

**راه A — با AI (پیشنهادی برای شروع):**
1. به ASSET_GENERATION_GUIDE_FA.md بروید و Prompt آماده همان Asset را کپی کنید.
2. در ابزار تولید تصویر بچسبانید. اگر چند خروجی داد، بهترین را انتخاب کنید و ۳ چیز را چک کنید: زاویه درست باشد (Top-Down سه‌ربع)، سبک کارتونی باشد، پس‌زمینه ساده/تک‌رنگ باشد.
3. قانون سند مادر (بخش ۳۷): هرگز خروجی AI را بدون بررسی وارد پروژه نکنید — چک‌لیست بالا حداقل بررسی است.

**راه B — دستی در Photopea:**
1. File → New → اندازه را از جدول Inventory بگذارید (مثلاً 256×448).
2. با ابزار قلم/شکل ساده بکشید. خط دور ضخیم (8-10px) فراموش نشود — این «امضای سبک» بازی ماست.
3. لایه پس‌زمینه را حذف/مخفی کنید تا شفاف بماند.

## گام ۴ — پس‌زمینه را حذف کنید (اگر AI تولید کرده)

در Photopea:
1. عکس را باز کنید (File → Open).
2. منوی **Select → Select Subject** بزنید (خودش موضوع را انتخاب می‌کند).
3. **Select → Inverse** (یعنی حالا پس‌زمینه انتخاب شده).
4. کلید Delete → پس‌زمینه پرید و شطرنجی (شطرنجی = شفاف) شد.
5. اگر لبه‌ها زشت بود: Select → Modify → Contract (2px) قبل از Delete.

> 💡 اگر تصویر AI پس‌زمینه سبز خالص داد، در Photopea: Select → Color Range → کلیک روی سبز → Delete.

## گام ۵ — PNG/WebP خروجی بگیرید

1. File → Export As → **PNG** (برای Spriteها — همیشه).
2. نام فایل را دقیقاً از Inventory کپی کنید: مثلاً `veh_player_01.png` — نه «car.png» نه «final.png»! (قانون نام‌گذاری بخش ۳).
3. برای تصاویر بزرگ تمام‌صفحه (Splash) → **WebP** با کیفیت 80.

## گام ۶ — اندازه را تنظیم کنید

- اگر عکس AI بزرگ‌تر از اندازه جدول است: Image → Image Size → اعداد جدول را بزنید (مثلاً 1024×1792 → 256×448).
- ⚠️ کوچک کردن OK است؛ بزرگ کردن (Upscale) تصویر کارتونی را تار می‌کند — نکنید.
- مهم: نسبت (نسبت عرض به ارتفاع) باید حفظ شود؛ زنجیر (link icon) در پنجره Image Size فعال باشد.

## گام ۷ — Sprite Sheet بسازید (فقط برای انیمیشن‌ها)

انیمیشن‌های ما ساده‌اند (دود، سکه، ستاره). روش دستی:
1. هر فریم را جدا بسازید (مثلاً ۶ فریم دود 128×128).
2. فایل جدید بسازید به عرض 6×128=768 و ارتفاع 128.
3. فریم‌ها را دقیقاً کنار هم بچینید (از View → New Guide Layout برای شبکه کمک بگیرید).
4. Export PNG با نام `fx_smoke_01_sheet.png`.
5. مشخصات (فریم/FPS/Loop) را در Inventory آپدیت کنید — مثال:

```text
Animation: fx_smoke_01
Frames: 6
FPS: 10
Loop: Yes
```

## گام ۸ — فایل را داخل پروژه بگذارید

1. فایل را با نام دقیق، در مسیر دقیقِ جدول Inventory کپی کنید.
   مثال: `veh_player_01.png` → پوشه `public/assets/vehicles/player/`
2. اگر پوشه وجود ندارد، خودتان بسازید (همان نامی که جدول می‌گوید).
3. تمام! **نیازی به تغییر کد نیست** — AssetManager خودش فایل را پیدا می‌کند (به همین دلیل معماری را «Data-Driven» ساختیم).
4. اگر Asset جدیدی است که در manifest نیست، طبق ASSET_IMPORT_GUIDE_FA.md یک خط به manifest اضافه کنید.

## گام ۹ — بازی را اجرا کنید و ببینید

1. پیش‌نمایش بازی را باز کنید (لینک Preview).
2. از منو، Free Drive را بزنید.
3. اگر ماشین/شیء شما دیده شد → موفق شده‌اید 🎉
4. اگر Placeholder (مربع برچسب‌دار) دیدید → یعنی بازی هنوز فایل شما را پیدا نکرده؛ ۹۰٪ موارد یعنی نام یا مسیر با جدول فرق دارد. دوباره حرف‌به‌حرف مقایسه کنید (حروف بزرگ/کوچک مهم است!).

## گام ۱۰ — مطمئن شوید درست Import شده (چک‌لیست)

- [ ] Placeholder مربوطه دیگر نمایش داده نمی‌شود
- [ ] تصویر سرجایش است (ماشین روی جاده، نه معلق در هوا)
- [ ] دور تصویر «مربع سفید/رنگی» دیده نمی‌شود (یعنی شفافیت خراب شده)
- [ ] ابعاد درست است (تصویر خیلی بزرگ/کوچک نیست — اگر ذره‌بین‌وار بزرگ است یعنی ابعاد جدول رعایت نشده)
- [ ] اگر انیمیشن است: سرعتش طبیعی است
- [ ] ابزار اعتبارسنجی (`bun run validate:assets` یا `node scripts/validate_assets.mjs`) خطای جدیدی نمی‌دهد

# بخش ۲ — راهنمای ۲۰ سؤالی هر نوع Asset

برای هر «نوع» Asset، ۲۰ سؤال سند مادر را یک‌بار برای همیشه جواب می‌دهیم. (مقادیر ابعادِ دقیق هر Assetِ مشخص = جدول Inventory.)

## 2.1 — ماشین‌ها (Vehicles)

1. **چیست؟** تصویر کارتونی ماشین از بالا با کمی زاویه (سه‌ربع).
2. **کجا استفاده می‌شود؟** ماشین بازیکن و ماشین‌های ترافیک در شهر.
3. **ضروری؟** VEH-001 اجباری؛ بقیه طبق جدول.
4. **تصویر/انیمیشن/صدا؟** تصویر ثابت؛ چرخش را خود بازی با کد انجام می‌دهد.
5. **ابعاد؟** 256×448 پیکسل (Canvas اسپرایت)؛ خود ماشین حاشیه ~10px خالی داشته باشد تا سایه دورش دیده شود.
6. **نسبت؟** 4:7 ثابت.
7. **فرمت؟** PNG.
8. **حجم؟** زیر 80KB (با squoosh فشرده کنید).
9. **چند فریم؟** 1 (Idle/Drive با جابه‌جایی چند پیکسلیِ کد شبیه‌سازی می‌شود).
10. **پس‌زمینه شفاف؟** بله، حتماً.
11. **نام فایل؟** `veh_player_01.png` (الگو: veh_نقش_شماره).
12. **پوشه؟** `public/assets/vehicles/player/` (طبق جدول هر ماشین).
13. **چطور ساخته شود؟** AI با Prompt آماده (بخش ۳ هندبوک/سند Generation) یا رسم دستی فلت.
14. **Prompt AI؟** در ASSET_GENERATION_GUIDE_FA.md — VEH-001 آماده است.
15. **اگر آماده دانلود کردم؟** کارتونی، Top-Down، فلت، بدون پس‌زمینه، مجوز آزاد (CC0/CC-BY). از بازارهای Asset چک کنید: License = CC0 بهتر است.
16. **تبدیل فرمت؟** هر تصویری → Photopea → حذف پس‌زمینه → Image Size به 256×448 → Export PNG.
17. **وارد کردن؟** کپی در مسیر جدول؛ تمام.
18. **استفاده در بازی؟** AssetManager با ID (`veh_player_01`) می‌خواند؛ VehicleController رسمش می‌کند و با زاویه حرکت می‌چرخاند.
19. **تنظیمات Import؟** ندارد (برخلاف Unity/Godot). فقط ابعاد و نام درست.
20. **اشتباهات رایج؟** نمای پهلو به‌جای بالا؛ پس‌زمینه سفید باقی‌مانده؛ سایه‌ای که با ماشین نمی‌چرخد؛ جزئیات خیلی ریز (روی موبایل شلوغ می‌شود)؛ برند واقعی کپی‌شده.

## 2.2 — پرتره شخصیت‌ها (Character Portraits)

1. چیست؟ نیم‌تنه/چهره شخصیت برای حباب دیالوگ.
2. کجا؟ کنار جملات طنز (راننده، پلیس، مسافر، مکانیک).
3. ضروری؟ CHAR-001 اجباری.
4. تصویر ثابت با چند «حالت» (عادی/خوشحال/شوک) = هر حالت یک فایل جدا.
5. ابعاد: 512×512.
6. نسبت: مربع 1:1.
7. فرمت: PNG.
8. حجم: زیر 120KB.
9. فریم: 1 (حالت‌ها فایل جدا هستند).
10. شفاف: بله.
11. نام: `char_driver_01_idle.png` / `_happy` / `_shock`.
12. پوشه: `public/assets/characters/player/`.
13. ساخت: AI (Prompt آمده) یا رسم کارتونی ساده با چشم‌های بزرگ.
14-20: مثل ماشین‌ها؛ اشتباه رایجِ مخصوص: چهره‌های «واقع‌گرایانه» که با سبک کارتونی نمی‌خواند — هرگز.

## 2.3 — کاشی‌های زمین (Tiles)

1. چیست؟ مربع‌های تکرارشونده زمین: آسفالت، پیاده‌رو، حیاط.
2. کجا؟ کل سطح شهر.
3. ضروری؟ ENV-001 تا 004 اجباری (قلب بصری بازی).
4. تصویر ثابت.
5. ابعاد: 512×512.
6. نسبت: 1:1.
7. فرمت: PNG.
8. حجم: زیر 150KB.
9. فریم: 1.
10. شفاف: **نه** — کاشی‌ها پر هستند (خودشان پس‌زمینه‌اند).
11. نام: `env_road_straight_01.png`.
12. پوشه: `public/assets/environments/roads/`.
13. ساخت: AI با کلمه کلیدی «seamless tileable texture» یا رسم دستی.
14. Prompt: در سند Generation.
15. آماده: texture های فلت CC0 (مثل Kenney.nl — مجوز CC0، استفاده تجاری آزاد ✅).
16. تبدیل: resize به 512×512 + Export PNG.
17. وارد کردن: مسیر جدول.
18. استفاده: World کاشی‌ها را در شبکه می‌چیند.
19. تنظیمات: ندارد؛ فقط **باید Seamless باشد**.
20. اشتباهات: لبه‌های درزدار؛ سایه داخل کاشی (سایه نباید Tile شود!)؛ خط‌چین جاده‌ای که الگوش می‌پرد.

## 2.4 — ساختمان‌ها و Prop ها

تقریباً مثل ماشین‌ها با این تفاوت‌ها:
- ابعاد و نام از جدول (ساختمان 512×640، Propهای کوچک 96 تا 192).
- شفاف: بله (روی کاشی زمین می‌نشینند).
- سایه ملایم زیر ساختمان داخل فایل OK است.
- Propها باید «یک نگاه» قابل تشخیص باشند: Silhouette واضح.
- اشتباه رایج: جزئیات زیاد در Prop کوچک — روی موبایل به «لکه» تبدیل می‌شود.

## 2.5 — UI و آیکون‌ها

1. چیست؟ دکمه‌ها، پنل‌ها، آیکون‌های HUD (سکه، آبرو، بنزین...).
2. کجا؟ منوها و صفحه بازی.
3. ابعاد: آیکون 128×128، دکمه 256×128، پنل 512×512.
4. فرمت: PNG.
5. حجم: زیر 25KB آیکون، زیر 40KB دکمه.
6. شفاف: بله.
7. نام: `ui_icon_coin.png` / `ui_button_01.png`.
8. پوشه: `public/assets/ui/` و `public/assets/icons/`.
9. نکته سبک: خط دور ضخیم مثل بقیه بازی + رنگ‌های شاد؛ آیکون باید در 40×40 پیکسل هم خوانا باشد (روی صفحه کوچک کوچک نمایش داده می‌شود).
10. اشتباهات: متن داخل آیکون (متن فارسی UI را کد می‌نویسد، نه عکس — تا همیشه تیز باشد)؛ آیکون‌های خیلی پرجزئیات.

## 2.6 — افکت‌ها (Sprite Sheet)

1. چیست؟ انیمیشن‌های کوتاه: دود، ستاره، برخورد.
2. ابعاد فریم: 128×128 — در یک ردیف کنار هم (Sheet).
3. فریم: 4 تا 6 | FPS: 10-12 | Loop: بله (دود) / خیر (برخورد).
4. نام: `fx_smoke_01_sheet.png` — عرض Sheet = تعداد فریم × 128.
5. شفاف: بله.
6. اشتباهات: فریم‌ها با فاصله/اندازه ناهماهنگ؛ شروع انیمیشن از وسط (باید «از هیچ» شروع شود).

## 2.7 — صدا: SFX

1. چیست؟ افکت‌های کوتاه: بوق، ترمز، تصادف، کلیک.
2. فرمت: WAV برای کار، **OGG برای بازی** (حجم کم، کیفیت خوب، پشتیبانی کامل اندروید).
3. Sample Rate: 44100Hz | Mono | 16bit.
4. طول: 0.1 تا 2 ثانیه.
5. حجم: زیر 100KB هر فایل.
6. نام: `sfx_horn_01.ogg`.
7. پوشه: `public/assets/audio/sfx/`.
8. ساخت: با Audacity (تولید نویز/تن) یا دانلود CC0 (freesound.org — حتماً فیلتر CC0).
9. تبدیل: Audacity → File → Export → OGG، کیفیت 5.
10. اشتباهات: Stereo (حجم دوبرابر)؛ بلندی نامتوازن بین فایل‌ها (Normalize به ‎-16 LUFS یا حداقل ‎-3dB peak)؛ silent-start طولانی (سکوت اول فایل را Cut کنید — تاخیر پخش می‌سازد).

## 2.8 — صدا: جملات طنز (Voices)

1. چیست؟ صدای ضبط‌شده جملات دیالوگ («داداش چیزی نشد!»).
2. فرمت/مشخصات: مثل SFX (Mono 44.1kHz OGG) | طول 0.8-2s.
3. نام: `voice_crash_01.ogg` — شماره برای هر جمله‌ی مختلفِ همان رویداد.
4. پوشه: `public/assets/audio/voices/player/` (طبق جدول: police، passenger...).
5. چطور: خودتان ضبط کنید → راهنمای کامل در VOICE_RECORDING_GUIDE_FA.md؛ یا صدای AI.
6. نکته: جمله‌ها همین حالا به‌صورت **متن** نمایش داده می‌شوند؛ هر فایل صوتی که با نام درست بیاید، خودکار جایش را می‌گیرد.
7. اشتباهات: بلندگویی ناهماهنگ؛ خنده/هو در انتهای فایل (Cut کنید)؛ پس‌زمینه نویز.

## 2.9 — موسیقی

1. چیست؟ لوپ‌های پس‌زمینه منو/گیم‌پلی.
2. فرمت: OGG | Stereo مجاز | 44.1kHz | حجم زیر 2.5MB هر لوپ.

## 3.2 — هماهنگی سبک (Consistency Rule — بخش ۸ سند مادر)

هر Asset باید این ۸ چیز با بقیه مشترک داشته باشد:
1. سبک: کارتون فلت
2. زاویه: Top-Down سه‌ربع (ماشین‌ها) / فرونتال (پرتره‌ها)
3. نور: سایه ملایم پایین-چپ، بدون گرادیان سنگین
4. خط دور: ضخیم (~8-10px در ابعاد ماشین)
5. پالت رنگ: گرم و شاد (زرد، نارنجی، فیروزه‌ای، قرمز فرش) — پالت رسمی در سند Generation
6. جزئیات: کم و بزرگ (خوانا روی موبایل)
7. تناسب: ماشین شهری ~2 برابر عرض پیاده‌رو
8. حالت: بامزه و گرد، نه تیز و واقعی

> 💡 ترفند عملی: قبل از ساخت هر Asset جدید، اسکرین‌شات یک Asset قبلیِ تأییدشده را کنار ابزارتان بگذارید و مقایسه کنید.
